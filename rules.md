# Agent Execution Rules & Security Safeguards

## 1. Strict Sandboxing & Target Isolation
* **Docker Boundary:** All target MCP servers MUST run inside ephemeral Docker containers with non-root execution contexts, dropped Linux capabilities, and strict CPU/RAM cgroup limits.
* **Network Isolation:** Target containers must run on an isolated Docker bridge network (`internal=true`) with no outbound Internet routing unless explicitly required for the specific test scenario.
* **Dummy Data Only:** Mock sensitive assets (files, API keys, database records) mounted into target containers must strictly contain synthetic dummy data (e.g., `MOCK_FLAG{test_payload_token_123}`).
* **Host Protection:** Under no circumstances should synthetic attack payloads be executed against host system tools, host filesystems, or non-containerized network endpoints.

## 2. Software Architecture & Code Quality
* **Language & Versioning:** Modern Python 3.11+ using standard strict typing (`mypy --strict` compliant).
* **Concurrency:** Asynchronous IO (`asyncio`) must be used for all container stdio stream readers, HTTP/SSE transport channels, and LLM API calls.
* **Decoupled Architecture:** Core components (`TargetManager`, `MCPClient`, `AttackerSynthesizer`, `ResponseEvaluator`, `TUIDashboard`) must remain completely modular with clean abstractions and interface boundaries.
* **Error Resilience:** Robust timeout mechanisms (default 10s timeout) must wrap all container stdio reads and tool invocations to prevent frozen containers or infinite loops from hanging the CLI test driver.

## 3. Evaluation & Reporting Integrity
* **Severity Categorization:** Discovered vulnerabilities must be classified using standardized security metrics (CRITICAL, HIGH, MEDIUM, LOW) based on context exposure and severity.
* **Payload Reproducibility:** Every generated security finding in exported reports must record the exact tool schema, generated input payload, raw container stdout/stderr, and specific heuristic matching rule triggered.
* **Non-Destructive Testing:** Attacks generated by the local LLM must focus on privilege escalation, indirect prompt injection, and data leaks without intentionally corrupting container environment stability.
